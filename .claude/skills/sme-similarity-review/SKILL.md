# 신규 협의사업 유사·중복 후보 임베딩 분석 스킬

## 1. 목적과 산출물

정책평가팀이 사전협의 요청서를 받으면 "기존사업 중 무엇과 겹치는가"를 먼저 추려야 한다. 기존 중앙부처·지자체
사업은 수천 건이라 눈으로 고르면 누락과 편향이 생긴다. 이 스킬은 신규사업의 4개 축 서술과 기존사업 단위의 서술을
같은 임베딩 공간에 놓고 코사인 유사도를 가중합해, 검토자가 정성 검토할 **후보 10개**를 재현 가능하게 뽑는다.

산출물은 세 가지다.

1. `유사중복_검토_<사업명>.md` — 개조식(□ ○ - *) 검토보고서. 검토 개요·후보 10개 표·내역사업별 후보·유의사항
2. `유사도_산출결과_<사업명>.xlsx` — 기존사업 단위 전체 순위, 축별 유사도·가중점수·5단계 등급, 신규사업 내역사업별 시트, 가중치 시트, 공고매핑 시트
3. `new_project_profile.json` — 신규사업 4개 축 서술(전체·내역사업 단위). 재산출의 출발점이므로 반드시 함께 남긴다

결과는 **선별 지표**이지 중복 판정이 아니다. 보고서에는 이 점을 항상 명시한다.

## 2. 입력 자료

| 자료 | 포맷 | 필수 | 용도 |
|---|---|---|---|
| 사전협의 요청서(별지 1 + 자체점검표) | .hwpx/.hwp/.pdf | 필수 | 신규사업 4개 축 서술의 **기본자료** |
| 사업설명자료(예산세부내역 포함) | .hwpx/.hwp/.pdf | 선택 | 요청서에 없는 추진체계·세부내역 보강(보조자료) |
| 중앙부처 지원사업 공고정보 | .xlsx (사업개요 열에 ①목적/②내용/③대상/④규모) | 필수 | 기존사업 보강 자료(단위 모드에 따라 비교 단위로도 사용) |
| biz_info 내역사업·구조표·공고매핑 | Supabase `public.biz`, `biz_struct`, `gonggo` 추출 JSON | 권장 | 내역·내내역사업 단위 비교 풀 |

biz_info(https://kosievalteam.github.io/biz_info/)는 화면만 공개되고 자료는 로그인 전용 Supabase에 있다. 추출 방법과
자료 취급 규칙은 `references/data_sources.md`를 읽는다. **추출 JSON은 저장소에 커밋하지 않는다.**

## 3. 절차

### Step 0. 환경 준비

```bash
pip install torch sentence-transformers openpyxl pandas numpy
export HF_HUB_DISABLE_XET=1     # Hugging Face Xet 다운로드가 프록시에 막히는 환경 대비
```

임베딩 모델은 `BAAI/bge-m3`(다국어, 한국어 정책문서에 적합)를 CPU로 돌린다. 외부 임베딩 API 키가 없어도 된다.
CPU 4코어 기준 4,000단위 × 4축 ≈ 1시간이므로 반드시 백그라운드로 실행하고 로그 파일을 남긴다.
실행 중 프로세스를 멈출 때 `pkill -f similarity_check`는 자기 셸까지 잡으므로 `pgrep -f "[s]imilarity_check"`로 PID를 확인해 종료한다.

### Step 1. 신규사업 프로필 작성

1. `python scripts/extract_text.py 요청서.hwpx -o request.txt`(설명자료도 동일)로 본문을 뽑는다.
2. `references/profile_guide.md`의 축별 작성 규칙에 따라 `new_project_profile.json`을 쓴다. 구조는
   `assets/new_project_profile.example.json`을 그대로 따른다.
   - `units.전체`에 세부사업 전체, 내역사업이 둘 이상이면 `units.내역N_이름`을 추가한다. 내역사업 성격이 다르면(예: 실증 지원 + 인재 양성) 전체 단위만으로는 유사도가 희석되므로 내역 단위 비교가 필수다.
   - 요청서가 기본, 설명자료는 보조라는 우선순위를 지킨다. 설명자료에만 있는 수치는 서술에 넣되 보고서에 출처를 밝힌다.

### Step 2. 기존사업 자료 확보

- 공고정보 xlsx: 그대로 사용한다. `load_existing`이 사업개요 열을 ①~⑤ 마커로 분해한다.
- biz_info 자료: `references/data_sources.md`의 절차로 `biz_2025_2026.json`, `struct2025/ struct2026/`, `parents_full/`, `gonggo2025/ gonggo2026/`을 만든다. 행 수를 DB `count(*)`와 대조하고 표본 행의 md5를 비교해 전사 오류를 확인한다.
- 비교 단위는 **내역사업 또는 내내역사업**이 기본이다(`--level naeyeok`). 공고는 단위가 아니라 보강 자료로 붙인다.
  공고를 단위로 쓰면 같은 사업이 공고 수만큼 후보를 차지해 상위 10개가 왜곡된다. biz_info 자료가 없을 때만 공고 단위(`--level announcement`)로 돌리고 보고서에 한계를 적는다.

### Step 3. 산출 실행

```bash
python scripts/similarity_check.py --level naeyeok \
  --xlsx "2026년 중앙부처 지원사업 공고정보.xlsx" --biz biz_2025_2026.json \
  --struct struct2025 --struct struct2026 --parents-full parents_full \
  --gonggo gonggo2025 --gonggo gonggo2026 \
  --profile new_project_profile.json --out output/similarity --top 20 > run.log 2>&1 &
```

로그 첫 줄에서 단위 수(내역/내내역), 공고 매핑 건수를 확인한다. 끝나면 `output/similarity/similarity_scores.xlsx`와
`top10.json`이 생긴다. 산출 기준(가중치·등급·축 텍스트 구성)은 `references/methodology.md`에 있다.

### Step 4. 결과 해석

xlsx의 `전체` 시트에서 다음을 뽑아 보고서 근거로 삼는다.

- 분포: 평균·표준편차·최댓값, 평균+2σ를 넘는 단위 수, 상위 1%(p99) 기준선. 상위 10개가 이 기준선 위에 있는지 확인한다.
- 상위 10개의 축별 유사도와 등급, `연계공고`, `규모`, `시행방법`. 같은 세부사업의 내역·내내역이 여럿 들어오면 "실제 비교 대상 사업 수는 10개보다 적다"고 적는다.
- 상위권 내부의 **간격**(예: 4위와 5위 사이 2점 차)을 찾아 직접 중복 검토 대상과 연계·조정 검토 대상을 나눈다.
- 신규사업 내역사업별 시트에서 상위 5개를 뽑는다. 요청서 자체점검표나 설명자료가 비교·차별성 근거로 든 사업은 순위를 찾아 적는다(자체점검표의 판단을 데이터로 검증하는 대목이라 검토자가 가장 많이 본다).
- 지자체 사업·내내역 단위 상위도 별도로 본다. 국비 사업이 아니면 "중복수혜"보다 "연계" 관점으로 쓴다.
- 비교 풀에 없는 유형(기관 자체사업, 예산서 밖 사업 등)을 유의사항에 적는다.

### Step 5. 보고서 작성과 정합성 검토

`references/report_template.md`의 구조와 문체 규칙으로 .md 보고서를 쓴다. 작성 후 반드시 다음을 점검한다.

- 수치 대조: 본문의 모든 순위·점수·건수를 xlsx에서 다시 읽어 확인한다(특히 "모두 ~를 넘는다" 같은 전칭 서술).
- 위계 정합: □만 읽어도 결론이 서고, ○은 □의 근거, -는 ○의 수치·부연, *는 구체 예시인지 확인한다.
- 문체: 문어체, 중언부언 없음, 한 문장 한 주장.
- 결론 완화: "중복이다"가 아니라 "검토 대상이다"로 끝맺고, 지표의 한계(전달체계 축 편향, 내내역 상속, 공고 매핑 자동화)를 유의사항에 둔다.

결과 .md와 .xlsx, 프로필 json은 저장소(예: `similarity/results/`)에 커밋한다. 추출 원본 JSON은 커밋하지 않는다.

## 4. 산출 기준 요약

| 분석항목 | 지표(안) 배점 | 적용 가중치 | 비고 |
|---|---|---|---|
| 사업목적 | 20 | 21.05 | 목적 서술 + 정책목적 태그 |
| 지원내용 | 30 | 31.58 | 내용 + 규모 + 설명(공고) / 세부·내역 목적 + 공고 지원내용 + 세부내용 + 산출근거(내역사업) |
| 지원대상 | 30 | 31.58 | 대상 + 대상유형·업종 / 수혜대상 + 지원산업 |
| 전달체계 | 15 | 15.79 | 주관부처 → 수행기관, 시행방법(직접/출연/보조 등), 지원유형, 지원방식 키워드(바우처·교육·인턴십·실증·매칭 …) |

- 종합 유사도(0~100) = Σ 가중치 × 축별 코사인 유사도. 가중치는 지표(안) 합 95를 100으로 비례 조정한 값이며, 사용자가 다른 배점을 주면 `RAW_W`만 바꾼다.
- 5단계 등급(상이/낮음/보통/높음/동일)은 축별 유사도의 코퍼스 내 z-점수(0, 1, 2, 3 경계)로 매긴 **참고치**다. 지표(안) 환산점수는 등급을 배점 비율로 환산한 보조 지표이고 순위의 근거는 종합 유사도다.
- 내내역 단위는 사업목적·지원대상·전달체계를 부모 내역사업에서 상속한다. 같은 내역사업의 내내역끼리 점수가 비슷하게 나오는 이유를 보고서에 밝힌다.

## 5. 자주 겪는 함정

- **github.io가 막혀 있다**: biz_info 화면은 자료를 담지 않는다. Supabase MCP(또는 팀 계정 SQL)로 가야 한다. `data_sources.md` 참고.
- **Hugging Face 다운로드 실패**(`cas-server.xethub.hf.co`): `HF_HUB_DISABLE_XET=1`을 두고 다시 받는다.
- **공고가 하나의 내역사업에 몰린다**: 정상이다. 공고명이 세부사업명과 같고 괄호 안이 내역을 가리키는 구조(예: "핀테크 지원(금융 테스트)")는 괄호 어절로 내역·내내역을 고른다. 결과는 `공고매핑` 시트에서 확인하고, 틀린 연결은 보고서 유의사항에 적는다.
- **동일 수행기관 사업이 상위에 몰린다**: 전달체계 축이 수행기관으로 근사되기 때문이다. 지원내용 축으로 보정 해석하라는 문장을 넣는다.
- **2025년 내내역이 사라진다**: 같은 사업은 최신 연도만 남기므로 2026년에 내역사업으로 합쳐진 경우 2025년 내내역은 비교되지 않는다. 유의사항에 쓴다.
- **xlsx가 8MB를 넘는다**: 축별 텍스트 열 때문이다. 저장소에 올려도 되지만 PR 리뷰에는 .md를 쓰게 안내한다.

## 6. 파일 안내

- `scripts/similarity_check.py` — 전체 파이프라인(xlsx 파싱, biz 로딩, 임베딩, 가중합, 등급, xlsx/json 출력)
- `scripts/biz_units.py` — 내역·내내역 단위 구성, 공고명 퍼지 매핑(gonggo Dice 대조 → 세부사업명+괄호 어절 → 사업명 직접 대조)
- `scripts/extract_text.py` — hwp/hwpx/pdf 텍스트 추출(한컴 설치 불필요)
- `scripts/biz_export.sql` — Supabase 추출 질의 4종(열 별칭 고정)
- `scripts/validate_chunks.py` — 청크 JSON 행 수·id 범위 검증
- `references/methodology.md` — 축 텍스트 구성, 가중치·등급, 단위 규칙의 근거
- `references/data_sources.md` — xlsx 스키마, Supabase 테이블 구조, MCP 청크 추출 절차와 작업자 지시문
- `references/profile_guide.md` — 요청서에서 4개 축 서술을 뽑는 규칙과 예시
- `references/report_template.md` — 개조식 보고서 틀과 문체·점검 체크리스트
- `assets/new_project_profile.example.json` — 「청년 금융혁신 창업·일자리 확대 지원」 프로필 예시
