# 신규사업 프로필(new_project_profile.json) 작성 규칙

프로필은 임베딩의 질문문이다. 축이 섞이면 모든 기존사업과 고르게 비슷해져 변별력이 사라지므로, 각 축에 그 축의 내용만 넣는다.

## 구조

```json
{
  "사업명": "사업명 (부처·과, 연도 신규, 예산)",
  "출처": "사전협의 요청서(기본자료) + 사업설명자료(보조자료)",
  "units": {
    "전체": {"사업목적": "...", "지원대상": "...", "지원내용": "...", "전달체계": "..."},
    "내역1_<이름>": {...},
    "내역2_<이름>": {...}
  }
}
```

단위 이름은 그대로 xlsx 시트명이 된다(31자 제한). 내역사업이 하나뿐이면 `전체`만 둔다.

## 축별로 넣을 것 / 뺄 것

| 축 | 넣는다 | 뺀다 |
|---|---|---|
| 사업목적 | 정책목적 문장, 추진 사유(해소하려는 공백), 추진근거(법령·국정과제·기본계획), 성과지표 | 지원 메뉴 나열, 예산 |
| 지원대상 | 기업 유형·업력·규모·분야, 개인(연령·신분), 참여 기관(금융회사·대학 등) | 지원 내용 |
| 지원내용 | 내역사업별 지원 메뉴를 번호로 나열, 규모(건수·인원·금액), 단계(공모→선정→실증→매칭) | 배경 설명 |
| 전달체계 | 주관부처 → 수행기관(시행방법: 기관보조/출연/직접수행/위탁), 자금 성격(국고보조금), 지원 방식(공모 선정, 바우처, 교육 운영, 인턴십 비용, 자부담률), 위탁 구조 | 정책 목적 |

## 출처 우선순위

1. 사전협의 요청서 별지 1(사업개요·정책목적·성과지표·지원대상·지원내용·지원규모·시행방법)이 기본이다. 체크박스 상태는 추출 과정에서 유실되므로 선택지 목록이 아니라 서술 내용만 근거로 삼는다.
2. 사업설명자료는 추진체계·세부 추진계획·예산 산출근거를 보강하는 데만 쓴다. 설명자료 버전(예: "예산세부내역 변경전")을 `출처`에 적는다.
3. 요청서와 설명자료가 다르면 요청서를 따르고 보고서 유의사항에 차이를 적는다.

## 작성 요령

- 전체 단위의 지원내용은 내역사업을 ①, ②로 나눠 쓰고 각 내역사업의 핵심 메커니즘(예: "2단계 실증 후 금융회사 매칭")을 명시한다.
- 숫자는 단위와 함께 쓴다(10건, 1,000명, 600백만원). 임베딩은 숫자 자체보다 "규모가 있다"는 서술을 본다.
- 150~400자가 적당하다. 너무 길면 일반어가 지배해 유사도가 평준화된다.
- 기존사업명을 프로필에 적지 않는다(해당 사업과의 유사도가 인위적으로 오른다).

## 예시

`assets/new_project_profile.example.json` — 「청년 금융혁신 창업·일자리 확대 지원」(금융위, ’27 신규 5,000백만원).
내역1 금융 AI 실증·매칭(3,000백만원), 내역2 금융혁신 청년인재 육성(2,000백만원)으로 나눴다.
