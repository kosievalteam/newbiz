# 사전협의 유사·중복 분석 방법론 재현성 명세서

- 작성일: 2026-11-23
- 대상: 이 저장소(`kosievalteam/newbiz`)의 사전협의 유사·중복 분석 파이프라인
- 조사 방식: **읽기 전용**. 코드·설정·산출물·실행 흔적만 확인했고 분석을 재실행하거나 기존 파일을 변경하지 않았음
- 근거 우선순위: 실제 실행 코드 > 산출물에 남은 값 > 스킬 문서. 셋이 어긋나는 지점은 본문에 모두 표시함
- 표기 규칙: **[확인]** 코드·산출물로 직접 확인 / **[추론]** 코드에서 논리적으로 따라 나오나 실행으로 확인하지 못함 / **[미확인]** 확인 불가

## 0. 요약 — 먼저 알아야 할 네 가지

**(1) 산식·가중치·모델은 단일 파일에 고정되어 있고 재현 가능하다.** 종합 유사도는 `similarity/similarity_check.py` 한 파일의 상수와 20줄 남짓한 계산으로 전부 결정된다. 산출물(xlsx·직접비교 json)에 남은 값으로 산식을 역산해 재현을 확인했다(§4).

**(2) 그러나 최근 분석의 실제 실행 경로는 스킬 문서가 기술한 경로가 아니다.** 스킬은 `--level naeyeok --biz … --struct … --gonggo …`를 전제하지만, 최근 분석은 모두 미리 만들어 둔 코퍼스 CSV를 `--extra`로 넣는 경로로 실행됐다. 산출물의 `행` 열이 `corpus_3631_v2.csv:747` 형식인 것이 그 증거다(§2.3).

**(3) 그 코퍼스 CSV와 후처리 스크립트가 저장소에 없고, 현재 컨테이너에서 소실됐다.** `corpus_3631_v2.csv`, `v2030_전체_메타.xlsx`, 메타데이터 병합 스크립트 `finalize.py`는 스크래치패드에만 있었고 커밋된 적이 없다. 2026-11-23 현재 스크래치패드는 비어 있다. **따라서 지금 이 컨테이너에서 과거 분석을 그대로 재실행할 수 없다.** 다만 코퍼스의 4개 축 입력 텍스트는 커밋된 xlsx 산출물에 모두 남아 있어 **복원이 가능하다**(§4.5, §10).

**(4) 신규사업 축 텍스트는 코드가 만들지 않는다. 사람(LLM)이 쓴다.** 기존사업 축 텍스트는 `axis_texts()`가 템플릿으로 조립하지만, 신규사업 축 텍스트는 프로필 JSON의 문자열을 **그대로** 인코딩한다(`enc([spec[ax]])[0]`). 이 **비대칭**이 DB 기반 사업 간 전수 분석에서 가장 중요한 쟁점이다(§3.1, §11.2).

## 3. 분석방법론 상세

### 3.1 A. 입력자료 및 데이터 처리

#### 허용/제외 문서 **[확인]**
- 기본자료: 사전협의 요청서 별지 1 + 사업기획 자체점검표 + 유사중복 자체점검표
- 보조자료: 사업설명서(예산요구서·경상사업 설명서 등)
- 우선순위: 요청서 > 설명자료. 어긋나면 요청서를 따르고 차이를 보고서 유의사항에 기재(`profile_guide.md`)
- **담당자 성명·연락처는 프로필·보고서에 넣지 않는다**(운영 규칙, 코드 강제 아님)
- biz_info 추출 JSON은 로그인 전용 자료로 저장소·메신저·메일에 올리지 않는다(`data_sources.md`)

#### 파일별 추출 방식 **[확인]**

| 포맷 | 함수 | 방식 |
|---|---|---|
| HWP 5.x | `extract_text.extract_hwp` (L60) | `olefile`로 OLE 열기 → `FileHeader` 36–40바이트의 bit0으로 압축 여부 판정 → `zlib.decompress(data, -15)` → `BodyText/Section0` 레코드 순회. 레코드 헤더 4바이트 LE: `tag=h&0x3FF`, `level=(h>>10)&0x3FF`, `size=(h>>20)&0xFFF`(0xFFF면 다음 4바이트). `HWPTAG_PARA_TEXT=67` 페이로드를 UTF-16LE 디코딩, 확장 제어문자 `{1,2,3,11,12,14,15,16,17,18,21,22,23}`·인라인 `{4,5,6,7,8,9,19,20}`은 16바이트 점유로 건너뜀 |
| HWPX | `extract_text.extract_hwpx` (L92) | zip에서 `Contents/section*.xml`을 읽어 태그 제거 |
| PDF | `extract_text.extract_pdf` (L116) | — |

- `extract_text.py`는 표 경계를 `[TABLE]`·`[CELL]` 마커로 남긴다. **최근 분석이 쓴 즉석 추출기에는 이 마커가 없다.** **[확인]**
- **체크박스(☑/□) 표식은 추출 과정에서 유실된다.** `profile_guide.md`가 명시하고 있고, 최근 분석 3건 모두 "체크박스 표식 소실로 지원분야·정책분야가 축 서술에 반영되지 않았음"을 유의사항에 기재했다. **따라서 자체점검표의 지원분야·정책분야·지원대상 유형 체크 결과는 분석에 들어가지 않는다.** **[확인]**

#### 4개 축 입력 텍스트 구성 — **두 경로가 다르다** **[확인]**

**(가) 기존사업 경로** — `axis_texts(df)` (L180–186). 템플릿 조립:

| 축 | 조립식 |
|---|---|
| 사업목적 | `f"{목적} (정책목적: {정책목적 or 대분류})"` |
| 지원내용 | `f"{내용} {'규모: '+규모 if 규모 else ''} {설명}".strip()` |
| 지원대상 | `f"{대상} (대상유형: {대상유형}, 업종: {업종})"` |
| 전달체계 | `delivery_text(r)` (L165–177) = `f"주관부처 {부처} → {method}. 지원유형 {대분류}/{중분류}. 지원방식: {키워드}. 규모: {규모}"` |

`method`는 `시행방법` 열이 있으면 `f"수행기관 {기관}, 시행방법 {시행방법}"`, 없으면 `직접수행` 또는 `f"수행기관 {기관}(기관보조·위탁)"`. 지원방식 키워드는 `내용+규모+설명`을 이어 붙인 문자열에서 `DELIVERY_KW`(L45–52) 28쌍을 **대소문자 무시 부분문자열**로 찾아 라벨을 중복 없이 나열하며, 없으면 `미상`.

**(나) 신규사업 경로** — `q = enc([spec[ax]])[0]` (L293). **프로필 JSON의 문자열을 가공 없이 그대로 인코딩한다.**

> **이 비대칭이 방법론의 핵심 구조다.** 기존사업 쪽에는 `(정책목적: …)`, `(대상유형: …, 업종: …)`, `주관부처 … → 수행기관 …` 같은 **고정 접미·접두 문구**가 항상 붙지만 신규사업 쪽에는 붙지 않는다. 즉 두 벡터는 **같은 서식으로 쓰인 문장끼리 비교되는 것이 아니다**. 이 설계는 "신규사업 1건 대 기존사업 N건"에서는 모든 후보에 동일하게 작용하므로 **순위에 편향을 주지 않지만**, 절대값 수준을 결정하고, **사업 간 비교에서는 어느 쪽 경로를 쓰느냐가 결과를 바꾼다**(§11.2).

#### 유사도 수식 **[확인]**

축 $ax \in \{$사업목적, 지원내용, 지원대상, 전달체계$\}$, 기존사업 단위 $i$, 신규사업 단위 $u$에 대해

$$\mathbf{e}^{ax}_i = \frac{f(t^{ax}_i)}{\lVert f(t^{ax}_i)\rVert_2}, \qquad \mathbf{q}^{ax}_u = \frac{f(s^{ax}_u)}{\lVert f(s^{ax}_u)\rVert_2}$$

$$\mathrm{cos}^{ax}_{i,u} = \mathbf{e}^{ax}_i \cdot \mathbf{q}^{ax}_u \qquad \text{(L294: } \texttt{sim = emb[ax] @ q}\text{)}$$

$$\boxed{\;S_{i,u} = \sum_{ax} W_{ax}\,\mathrm{cos}^{ax}_{i,u}\;} \qquad \text{(L301: } \texttt{total += sim * W[ax]}\text{)}$$

여기서 $f(\cdot)$는 bge-m3 인코더, $t^{ax}_i$는 `axis_texts()` 조립 텍스트, $s^{ax}_u$는 프로필 문자열.

#### 가중치 **[확인]**
```python
RAW_W = {"사업목적": 20, "지원내용": 30, "지원대상": 30, "전달체계": 15}   # L33, 합 95
W = {k: v / sum(RAW_W.values()) * 100 for k, v in RAW_W.items()}       # L34
```

| 축 | 지표(안) 배점 | 적용 가중치 $W_{ax}$ | 정확값 |
|---|---|---|---|
| 사업목적 | 20 | 21.05 | 21.0526315789474 |
| 지원내용 | 30 | 31.58 | 31.5789473684211 |
| 지원대상 | 30 | 31.58 | 31.5789473684211 |
| 전달체계 | 15 | 15.79 | 15.7894736842105 |
| 합계 | 95 | **100.00** | 100.0 (검증 완료) |

> 가중치는 **xlsx `가중치` 시트에 매번 기록**되므로 산출물만으로 사후 확인 가능. 사용자가 다른 배점을 주면 `RAW_W`만 바꾼다(SKILL.md §4).

#### 등급과 지표(안) 환산점수 **[확인]**

축별 코사인을 **코퍼스 내 z-점수**로 바꿔 5단계로 나눈다.

$$z^{ax}_{i,u} = \frac{\mathrm{cos}^{ax}_{i,u} - \mu^{ax}_u}{\sigma^{ax}_u}, \qquad \mu^{ax}_u,\ \sigma^{ax}_u \text{: 해당 코퍼스 전체의 평균·표준편차}$$

(L295. `numpy`의 `.std()` 기본값이므로 **모표준편차 ddof=0**)

$$\text{등급} = \mathrm{GRADE\_NAME}\big[\textstyle\sum_{c \in \{0,1,2,3\}} \mathbb{1}[z \ge c]\big] \qquad \text{(L190)}$$

| z 구간 | 등급 | 사업목적 | 지원내용/지원대상 | 전달체계 |
|---|---|---|---|---|
| $z<0$ | 상이 | 0.0 | 0.0 | 0.0 |
| $0\le z<1$ | 낮음 | 5.3 | 6.3 | 3.2 |
| $1\le z<2$ | 보통 | 10.5 | 14.7 | 7.4 |
| $2\le z<3$ | 높음 | 15.8 | 23.2 | 11.6 |
| $z\ge3$ | 동일 | 21.1 | 31.6 | 15.8 |

지표(안) 환산점수 $= \sum_{ax} \mathrm{GRADE\_RATIO}[ax][\text{lvl}] \times W_{ax}$ (L191, L302).

> **등급은 절대 임계값이 아니라 코퍼스 상대 기준이다.** 비교 풀이 바뀌면 같은 사업의 등급이 바뀐다. **순위의 근거는 종합 유사도이고 등급·환산점수는 참고치다.** 그리고 **소수(N<30)끼리 비교할 때는 z-점수가 의미를 잃어 산출하지 않는다**(직접비교 산출물에 등급 열이 없는 이유).

#### 비교 후보군 구성과 검색 방식 **[확인]**
- **전수 계산.** 근사 최근접 탐색(ANN)·색인 없음. $N \times 1024$ 행렬과 질의 벡터의 **단일 내적**(`emb[ax] @ q`)으로 전체를 한 번에 계산
- 지역 필터 `--region`: `LOCAL_GOVS`(17개 시도, L81–82)에서 지정 시도를 뺀 집합과 `부처` 열이 **정확히 일치**하는 행을 제외(L270–282). **임베딩 계산 뒤에 적용**되므로 전체 코퍼스 캐시를 그대로 재사용한다
- 최근 사례의 코퍼스 규모: 전체 3,631단위 → 경남 1,233 / 부산 1,222 / 충남 1,153 / 전북 1,264 / 경북 1,289 (중앙부처 1,052 + 해당 시도) **[확인]**

#### 순위·동점 처리 — **주의가 필요한 지점** **[확인]**

```python
res["종합유사도(0~100)"] = np.round(total, 2)                              # L303  ← 먼저 2자리 반올림
res = res.sort_values("종합유사도(0~100)", ascending=False).reset_index(drop=True)  # L305  ← 그 값으로 정렬

```

- **정렬은 반올림된 2자리 값으로 한다.** 따라서 2자리에서 같아진 단위가 대량으로 생긴다
- `pandas.sort_values`의 기본 `kind="quicksort"`는 **불안정 정렬**이다
- 실측(2026-0319, 1,222단위): **동점군 300개, 동점에 속한 행 734개(60.1%)**. 동점군 내부 원본 행번호 순서는 오름차순 116군 / 내림차순 108군 / 뒤섞임 76군 → **원본 순서를 보존하지 않음이 확인됨**

> **결론: 동점 구간의 순위는 산술적 의미가 없고 정렬 알고리즘의 산물이다.** 같은 입력·같은 라이브러리 버전이면 같은 결과가 나오지만, **코퍼스 행 순서가 바뀌거나 numpy/pandas 버전이 바뀌면 동점 내부 순위가 달라질 수 있다.** 상위 20위 안에서도 동점이 발생한다(2026-0316의 13·14위 모두 63.57). 보고서에서 동점을 명시적으로 서술해 온 것은 적절한 대응이었다.

## 9. 검증된 사항과 미확인 사항

### 9.1 검증됨 **[확인]**
1. 가중치 4개 값과 합 100
2. 종합 유사도 = Σ W×cos (xlsx 1,222행·직접비교 57행 전수 역산)
3. 가중점수·참고2지표점수의 반올림 규칙
4. 등급이 코퍼스 z-점수 기반임(99.75%+ 재현)
5. 스킬/`similarity` 두 사본의 md5 동일
6. 최근 분석이 `--extra` 경로로 실행됨

## 11. DB 기반 사업 간 전수 유사도 분석에 기존 방법론을 그대로 재사용하는 방법

### 11.1 그대로 재사용할 수 있는 것 **[확인]**

| 재사용 대상 | 호출 방법 |
|---|---|
| `AXES`, `RAW_W`, `W` | `from similarity_check import AXES, RAW_W, W` |
| 인코딩 | `model.encode(xs, normalize_embeddings=True, batch_size=16)` |
| 코사인 | 정규화 벡터의 내적 |
| 종합 산식 | `sum(cos[ax]*W[ax] for ax in AXES)` |
| 기존사업 축 조립 | `from similarity_check import axis_texts, delivery_text, load_biz, load_extra` |
| 단위 구성 | `from biz_units import build_units` |

**이 조합은 이미 `direct_compare.py`가 수행하고 있으며**(L8, L20–30), 본 명세서의 검증에서 **직접비교 57행 전부가 Σ W×cos로 재현**됐다. 즉 **사업 간 비교를 위해 새 산식을 만들 필요가 없다.**

### 11.2 **반드시 결정해야 할 한 가지 — 축 텍스트 경로**

현재 두 경로가 공존한다.

| 경로 | 함수 | 적용 대상 | 접두·접미 문구 |
|---|---|---|---|
| **P (profile)** | `enc([spec[ax]])[0]` | 신규 협의사업 | 없음(LLM 작성 원문) |
| **T (template)** | `axis_texts(df)` | 기존사업 | `(정책목적: …)`, `(대상유형: …, 업종: …)`, `주관부처 … → 수행기관 …` 등 |

- 지금까지의 개별 분석은 **P × T** 조합이다
- `direct_compare.py`가 수행한 협의사업 간 비교는 **P × P** 조합이다

**→ 2026년 중앙부처 사전협의 전수 DB에서 사업 간 유사도를 낼 때는 전 쌍이 동일 경로여야 한다. 협의사업끼리 비교하므로 `direct_compare.py`와 같은 P × P가 기존 방법론과 일관된 선택이다.**

> **중요**: P × P로 낸 점수는 **P × T로 낸 기존 개별 분석의 점수와 같은 척도가 아니다.** 축 텍스트 서식이 다르므로 절대값 수준이 다르다. 두 결과를 한 표에 섞거나 "협의사업 간 70점 > 기존사업 대비 65점" 식으로 비교해서는 안 된다. 기존 보고서들이 직접비교 결과에 대해 "코퍼스 순위와 같은 척도가 아니다"라고 명시해 온 것과 같은 원칙이다. **이것은 방법론의 한계이지 임의 보완 대상이 아니다.**

### 11.3 대칭성 — 비교 건수 결정 근거 **[확인]**

$$S_{A,B} = \sum_{ax} W_{ax}\,(\mathbf{q}^{ax}_A \cdot \mathbf{q}^{ax}_B) = \sum_{ax} W_{ax}\,(\mathbf{q}^{ax}_B \cdot \mathbf{q}^{ax}_A) = S_{B,A}$$

내적은 교환법칙이 성립하고 가중치는 방향에 무관하므로 **산식이 대칭이다.** 과거 경상북도 4건 분석에서 전치행렬 최대 절대차 0이 실측으로 확인됐다(`대칭성검증_0279_276.json`).

**→ N개 사업의 전수 비교는 $N(N-1)/2$ 쌍이며, 방향을 나눈 $N(N-1)$은 중복이다.** 기능 단위를 포함하면 단위 수 $M$에 대해 $M(M-1)/2$ 쌍이 된다(A의 기능 × B의 기능 교차 포함).

> 단, **등급·지표(안) 환산점수는 대칭이 아니라 "산출 불가"다.** z-점수는 코퍼스 분포를 요구하는데 사업 간 비교에는 모집단이 없다. 전수 DB에서 N이 충분히 크면(수백 건) 코퍼스 z를 정의할 수 있으나, **그 z는 기존 개별 분석의 z(기존사업 3,631단위 기준)와 다른 모집단이므로 등급을 상호 비교할 수 없다.** 이 역시 한계로 명시해야 한다.

### 11.4 전수 계산 방식

축별로 $M \times 1024$ 정규화 행렬 $E_{ax}$를 만들면

$$\mathbf{S} = \sum_{ax} W_{ax}\, E_{ax} E_{ax}^{\top}$$

한 번의 행렬곱으로 전 쌍 점수가 나온다. 상삼각만 취하면 $M(M-1)/2$ 쌍. `emb[ax] @ q`(L294)를 벡터에서 행렬로 확장한 것일 뿐 **산식 변경이 아니다.**

메모리: $M=1{,}000$이면 $\mathbf{S}$는 약 8MB로 문제없다. $M$이 수만이면 블록 분할이 필요하다.

### 11.5 기존 코드를 손대지 않고 맞춰야 할 운용 조건

| 조건 | 이유 |
|---|---|
| `W`를 import해 쓰고 하드코딩하지 않는다 | `RAW_W` 변경 시 자동 반영 |
| `normalize_embeddings=True` 유지 | 내적=코사인 전제 |
| `max_seq_length`를 전 쌍에 동일하게 적용하고 기록 | 512/8192 분기 제거 |
| `model_revision` 고정·기록 | 최대 재현성 위험 제거 |
| 반올림은 **저장 시에만**, 비교·정렬은 원값으로 | 동점 양산·불안정 정렬 회피 |

| 등급·환산점수는 모집단을 명시하거나 산출하지 않는다 | §11.3 |

### 12.2 재현성 검증 기준 (실행 후)

**테스트 A — 산식 불변 (모델 없이 수행 가능)**
산출물의 축별 유사도(4자리)로 종합 유사도를 역산한다.
- **합격**: 최대 오차 **≤ 0.01**
- 근거: 본 조사에서 기존 xlsx 1,222행 최대 0.0079, 직접비교 57행 전부 통과

**테스트 B — 대칭성**
$\mathbf{S}$와 $\mathbf{S}^{\top}$의 최대 절대차.
- **합격**: **= 0**(또는 ≤ 1e-9)
- 근거: 과거 4건 비교에서 0 실측

**테스트 C — 기존 산출물 역검증**
기존 xlsx의 `*_텍스트` 열을 새 코드로 재인코딩해 기존 종합 유사도를 재현한다(`direct_compare.py` L39–48의 방식).
- **합격**: 차이 **≤ 0.05**
- **불합격 시 원인 분해**: 모델 revision / `max_seq_length` / 라이브러리 버전 / 텍스트 변형 순으로 확인
- **주의**: 역검증에 넣는 xlsx가 비교 대상(B)이 아니라 A쪽이면 값이 크게 벌어진다. 과거 사례에서 인자 선택 착오로 71.95 vs 67.29(차이 4.66)가 나온 적이 있다 — 대칭성 위반이 아니라 인자 오류였다

**테스트 D — 결정성**
같은 입력으로 2회 실행.
- **합격**: 전 쌍 점수 **완전 일치**

**테스트 E — 순위 안정성**
코퍼스 행 순서를 섞어 재실행.
- **합격**: 점수 불변, 순위도 불변(안정 정렬 + 2차 키 적용 시)
- 현재 코드로는 **불합격 예상**(동점 구간 변동) → §11.5 권고 적용 필요

**테스트 F — 척도 혼용 금지**
P×P 결과와 P×T 결과가 같은 표·같은 순위에 섞이지 않았는지 확인.
- **합격**: 산출물·보고서에서 분리 서술

### 12.3 차이 발생 시 원인 구분 기준

| 증상 | 원인 | 확인 |
|---|---|---|
| 점수가 전반적으로 조금씩 다름 | 모델 revision 변경 | 테스트 C 불합격 + 텍스트 동일 |
| 긴 텍스트 단위만 다름 | `max_seq_length` 차이 | 512자 초과 단위에 집중되는지 |
| 소수점 끝자리만 다름 | 라이브러리/BLAS 버전 | 오차 1e-5 규모 |
| 점수 같은데 순위가 다름 | 동점 + 불안정 정렬 | 동점군 분포 확인 |
| 특정 단위만 사라짐/추가됨 | 비교 풀 구성(`--region`, 목적 공란 제외, 중복 제거) | 단위 수 대조 |
| 축 하나만 크게 다름 | 축 텍스트 경로(P/T) 불일치 | `axis_build_path` 대조 |
| 전체가 크게 다름 | 프로필 축 서술 변경 | 프로필 md5 대조 |
